# CampusSkill 测试规范与用例文档（v11 可信交易保障体系）

> 定位：毕业设计第 5 章「系统测试」的证据底座。本文档约定测试分层、运行方式、用例书写模板，
> 并收录 v11 全部测试用例清单。新功能遵循"**功能与测试同步交付**"原则：每个资金/风控功能合并时必须带对应层级的测试。

---

## 一、测试分层策略

| 层级 | 技术 | 依赖 | 命名约定 | 运行方式 |
|---|---|---|---|---|
| L1 单元测试 | JUnit 5 + Mockito（Mock Mapper/Service） | 无外部依赖 | `XxxServiceTest`，位于 `service/` 包 | `mvn test -Dtest=XxxServiceTest`（默认 surefire 跑） |
| L2 集成测试 | SpringBootTest + 真实 MySQL/Redis | 本地 MySQL（`campus_runner_test` 库）+ Redis（database 1） | `XxxIT`，位于 `it/` 包 | `mvn test -Dtest=XxxIT`（类名以 IT 结尾，需配置 surefire/failsafe 或显式 -Dtest） |
| L3 端到端冒烟 | Node 脚本 `e2e/smoke.mjs`（HTTP 全链路） | 应用运行在 localhost:8080 | — | `node e2e/smoke.mjs` |
| L4 性能/并发压测 | `tools/loadtest/bench.mjs`（Node 并发压测）+ JMeter 方案 | 应用运行在 localhost:8080 + 数据工厂造数 | — | 见 `tools/jmeter/README.md` |

### L2 集成测试环境约定

- 独立库 `campus_runner_test`（结构与 `campus_runner` 一致），Redis 使用 database 1，与开发数据完全隔离（见 `application-test.yml`）。
- 测试数据一律通过 JdbcTemplate 直插或服务调用构造，并以时间戳 tag 命名（如 `it1719000000000_用户`），**不依赖、不污染既有数据**。
- 并发用例统一使用 `CountDownLatch`（ready/start 两段式）+ `ExecutorService`，断言"恰好 N 成功"与数据库最终一致。

### L1 用例书写模板

```java
@Test
@DisplayName("余额变动：金额为空或 0 直接拒绝")        // 用例名 = 被测行为 + 预期
void changeBalance_rejectsZeroOrNull() {              // 方法名 = 被测方法_场景
    // given（Mock 返回值）
    // when（调用被测方法）
    // then（assert 验证副作用 + 返回值）
}
```

- 一个用例只验证一个行为；异常路径必须有 `assertThrows`。
- 涉及规则/枚举组合的用例优先用 JUnit 5 `@ParameterizedTest`（表驱动），参数表即测试用例表，可直接贴进论文。

## 二、测试用例清单

### 2.1 钱包资金链路（已有，v11 前交付）

| 编号 | 层级 | 用例 | 断言要点 |
|---|---|---|---|
| W-01 | L1 | 余额变动金额为空/0 拒绝 | 不触发任何扣款与流水 |
| W-02 | L1 | 余额不足拒绝 | 抛 InsufficientBalanceException，不写流水 |
| W-03 | L1 | 收入方向记账 | 余额 +、累计收入 +、流水金额取绝对值 |
| W-04 | L1 | 支出方向记账 | 累计支出按负数绝对值累计 |
| W-05 | L1 | 懒开户 | 首次操作经 Redis 锁串行创建账户 |
| W-06 | L2 | 抢单竞态：30 人并发抢同一单 | 恰好 1 人成功，订单状态/接单人落库一致 |
| W-07 | L2 | 钱包对账：并发充值后并发扣款 | 余额 = 200 - 成功扣款总额，永不透支，每笔要么成功要么明确拒绝 |

### 2.2 资金对账（v11）

| 编号 | 层级 | 用例 | 断言要点 |
|---|---|---|---|
| R-01 | L1 | 流水符号映射（表驱动：6 种类型 × 符号） | 收入类(1,3,5)为正、支出类(2,4,6)为负 |
| R-02 | L1 | 一致钱包 | 期望余额=当前余额 → 不落差异记录 |
| R-03 | L1 | 差异钱包 | diff=余额-期望 → 落一条记录，含批次号/差异金额/流水数 |
| R-04 | L1 | 多钱包混合批次 | 只记差异行；返回批次汇总（检查数/差异数） |
| R-05 | L1 | 差异分类（表驱动：多收/少收/多扣/少扣） | 差异金额按 0.01 精度计算正确 |
| R-06 | L2 | 真实库对账闭环 | Jdbc 造账+流水 → 跑对账 → 差异行落库且字段正确 |

### 2.3 支付/提现幂等（v11）

| 编号 | 层级 | 用例 | 断言要点 |
|---|---|---|---|
| I-01 | L2 | 同一幂等键 20 线程并发充值 | 恰好 1 次成功，余额只加一次，其余收到"请勿重复提交" |
| I-02 | L2 | 同一幂等键并发支付同一订单 | 恰好 1 次扣款成功，订单只进入一次已支付态 |
| I-03 | L2 | 首次失败后同键重试放行 | 首次业务异常 → 键释放 → 同键重试可成功 |
| I-04 | L1 | 未携带幂等键的请求 | 直接放行（兼容旧客户端），不落幂等键 |

## 三、本轮（v11）验收口径

1. `mvn test`（L1）全绿；`mvn test -Dtest=GrabWalletConcurrencyIT,IdempotencyIT,ReconcileIT`（L2）全绿。
2. `node e2e/smoke.mjs`（L3）62+ 断言全通过。
3. 压测报告数据落盘 `docs/实验报告-v11-可信交易保障体系.md`（L4 产物）。
4. 压测结束后管理端对账批次差异 = 0。
