# 第 7 章 系统实验与分析（初稿）

> 本章两个实验均可现场复现：实验一 `node tools/recommend-experiment.mjs --users 10 --expose 6`（约 1 分钟）；
> 实验二 `node tools/loadtest-grab.mjs --concurrency 100 --rounds 8 --label <名称>`（约 3 分钟，含技能者账号自动构建）。
> 素材：`tools/loadtest/recommend-experiment-report.md`、`recommend-experiment.json`、`baseline100.json`、`optimized100.json`、`report.md`。

## 7.1 实验一：个性化推荐效果对比

### 7.1.1 实验目的

验证推荐引擎（第 6.4 节）能否将用户兴趣类目的服务有效前置，即回答："个性化推荐位是否比默认排序更能命中用户偏好并促成转化？"

### 7.1.2 实验设计

模拟"偏好驱动用户"的决策行为，设置实验组与对照组：

1. **兴趣注入**：为 10 名新注册用户各指定一个兴趣类目 C，并让该用户连续浏览 C 类目下 3 个服务——激活推荐引擎的类目偏好画像；
2. **两组曝光**（每组每人 6 次）：
   - 实验组「猜你喜欢」：取推荐接口返回的靠前服务，浏览行为以来源标记 `source=2` 记录；
   - 对照组「市场列表」：取默认销量排序中未浏览过的靠前服务（与个体兴趣无关），来源标记 `source=1`；
3. **转化规则**：用户只对兴趣类目 C 的服务产生预约（模拟真实兴趣决策），预约行为继承来源标记；
4. **指标**：兴趣类目命中率（曝光中类目 C 占比）、预约转化率 CTR（预约数 / 浏览数）。

数据采集基于 `user_behavior` 表的来源化行为埋点，平台侧聚合口径与管理端统计接口 `/admin/statistics/recommendEffect` 完全一致。

### 7.1.3 实验结果

| 指标 | 猜你喜欢（实验组） | 市场列表（对照组） |
|---|---|---|
| 兴趣类目命中率 | **36.7%**（22/60） | **0.0%**（0/60） |
| 预约转化数 | **22** | **0** |
| 预约转化率 CTR | **14.7%** | **0.0%** |

### 7.1.4 结果分析

推荐位的兴趣命中率显著高于默认排序，原因可解释：内容特征分中类目偏好权重占 0.5（内容特征内部），使历史行为类目在候选打分中占据优势；而市场默认排序仅依据销量与评分，与个体兴趣无关，命中率随类目分布随机，实验中为 0。

局限性与改进方向：①用户为模拟用户、兴趣决策为确定性规则，真实平台应以线上 A/B 灰度替代；②样本规模 10 用户 × 6 曝光，指标置信区间较宽；③未观测长期留存指标（复购、停留时长）。在论文中如实说明上述局限，并将"接入真实行为数据的 A/B 平台"列为后续工作。

## 7.2 实验二：抢单接口高并发优化

### 7.2.1 实验目的

量化第 6.1 节三项优化（Lua 原子化限流占位、接单权限本地缓存、SQL 索引）的实际收益，并验证优化不破坏正确性。

### 7.2.2 实验设计

- **场景**：N=100 个认证技能者（脚本自动完成建号→入驻→审核）在同一毫秒并发抢同一笔已支付订单，重复 8 轮（轮间隔 10.5 秒规避限流窗口对指标的污染）；
- **A/B 方法**：同一构建产物，通过启动参数 `--campus.grab.legacy=true` 切换基线实现（权限先查库 + 4 次 Redis 往返），除该开关外全部环境一致；
- **正确性断言**：每轮"恰好 1 人抢单成功"；
- **指标**：吞吐 QPS、平均/P95/最大时延。

### 7.2.3 实验结果

| 指标 | 基线实现 | 优化实现 | 变化 |
|---|---|---|---|
| 吞吐 QPS | 1226.3 | 1536.7 | +25.3% |
| 平均时延 | 58 ms | 47 ms | −19.0% |
| P95 时延 | 78 ms | 60 ms | −23.1% |
| 最大时延 | 114 ms | 106 ms | −7.0% |
| 正确性 | 8/8 轮恰好 1 人成功 | 8/8 轮恰好 1 人成功 | 均通过 |

### 7.2.4 结果分析

收益主要来自两处：①失败请求的成本从"1 次查库 ×2 + 3 次 Redis 往返"降为"1 次 Redis 往返"，在 100 并发下约 99% 的请求是失败者，其成本下降主导了整体 QPS 提升；②权限本地缓存消除了热点时段对数据库连接池（8 连接）的争用，反映在 P95 与平均时延的显著下降。

剩余瓶颈分析（可作为"进一步工作"）：抢单成功路径上的站内信与 WebSocket 推送为同步执行，构成尾部时延的主要成分，可异步化（项目已开启 @EnableAsync）；单订单竞争最终收敛为一行数据的行锁更新，吞吐上限由数据库单行写能力决定，更大规模需引入队列削峰或按类目分片。

### 7.2.5 实验可信度说明

A/B 两轮使用同一构建、同一机器、同一数据规模，唯一变量为实现开关；压测期间每轮成功数均被断言，避免"以正确性换性能"的虚假收益；原始数据以 JSON 形式随仓库留存，可复算。

## 7.3 本章小结

两个实验分别从"功能有效性"（推荐是否命中偏好并促转化）与"性能有效性"（优化是否带来可测收益且不破坏正确性）两个维度，为系统设计决策提供了数据支撑；实验脚本、原始数据与统计口径全部随仓库交付，具备完整的可复现性。
